# CosmosEdu

**Unity 6 + URP**로 만든 실시간 우주 전시 — 완전 나레이션이 붙은 교육 시뮬레이션 4종
(일반상대성이론 블랙홀 · 우리은하 · 태양계 · 성운과 성단)이 서로 연결되어 있고, 각각 데스크톱
쇼케이스와 Quest 패스스루(MR) 버전을 갖추고 있습니다.

*구 **BlackHoleEdu** — 프로젝트가 첫 이름보다 커졌습니다.*

**▶ 라이브 WebGL 데모: [cosmos-edu-783.netlify.app](https://cosmos-edu-783.netlify.app)**

*[English README](README.md)*

## 전시 구성 한눈에

타이틀 화면(빌드 인덱스 0)에서 언어와 체험을 고르고 시작합니다. 어느 씬에서든 타이틀로
돌아올 수 있습니다 (데스크톱은 툴바 버튼, MR은 메뉴 버튼). Quest APK는 패스스루 선택 화면인
`MRTitle`로 바로 부팅합니다. 헤드셋을 연결한 PC 빌드는 `TitleScreen`에서 시작해 HMD를 감지하면
`MRTitle`로 전환됩니다.

| 전시 | 데스크톱 씬 | MR 씬 |
|---|---|---|
| 타이틀 / 선택 | `TitleScreen` | `MRTitle` |
| 블랙홀 | `BlackHoleShowcase` | `BlackHoleMR` |
| 우리은하 | `MilkyWayShowcase` | `MilkyWayMR` |
| 태양계 | `SolarSystemShowcase` | `SolarSystemMR` |
| 성운과 성단 | `NebulaShowcase` | `NebulaMR` |

전시들은 이야기로도 이어져 있습니다: 블랙홀 씬은 궁수자리 A*이고, 은하 씬에서 은하 중심으로
다이빙하면 블랙홀 전시로 착지하며(F9), 태양계 투어의 마지막은 은하가 보이는 곳으로 돌아갑니다.

- **4개 언어** — 한국어 · English · 日本語 · 中文: UI·자막·라벨·나레이션(언어별 뉴럴 TTS) 전부. 언제든 전환 (K 또는 화면 선택기)
- **거의 전부 프로시저럴** — 스카이박스·은하·별 표면·사운드스케이프·중력파 처프 오디오까지 코드 생성.
  외부 에셋은 행성/달 실측 텍스처 맵, DSS2 심우주 서베이 사진(성운 배경, 출처 표기 포함),
  번들 CJK 폰트뿐
- **PC(주 타깃) · Quest 패스스루 · WebGL — 모바일 브라우저 포함**: 터치 조작, 16:9 레터박스,
  캡션 가독성을 위한 1280 기준 UI 레이아웃, 적응형 해상도 (전 셰이더 `target 3.5`; 웹은 URP/WebGL
  FSR 제한으로 포스트프로세싱 비활성)

## 1 · 블랙홀 (`BlackHoleShowcase` / `BlackHoleMR`)

화면의 모든 것 — 그림자·광자 고리·렌즈 상 — 은 셰이더에서 **매 픽셀 측지선 방정식을
수치적분**한 결과입니다. 밝기와 색은 상대론적 편이(도플러 비밍 · 중력 적색편이 · 흑체복사)로
계산됩니다.

- **슈바르츠실트 레이마칭** — 널 측지선 leapfrog 적분, 얇은 강착원반 + 대기 헤이즈, I ∝ (δ·g)³ 상대론적 비밍, T ∝ r^(−3/4) 박원반 온도, 플랑크 궤적 흑체색
- **커(회전) 블랙홀** — 커–실트 좌표 해밀토니안 적분, D자 그림자, 프레임 드래깅, ISCO(a) 자동 추적 (3키, 스핀 0→0.998)
- **이중 블랙홀 병합** — GW150914 시네마틱 (F4): 원반이 흩어지며 **별빛을 렌징하는 두 개의 맨 블랙홀**이 Peters 궤도로 나선 강하 — 실제 GW150914처럼 가스 없이 — 궤도 동기 처프 오디오, 사중극 변형 중력파 파면, 링다운, 커 잔해(질량 95% · 스핀 0.69)
- **체험 콘텐츠** — 11단계 나레이션 가이드 투어 (F1), 블랙홀 탄생 인트로 (F2), 전 구간 나레이션 1인칭 낙하 체험 (F3, 지평선 안쪽까지 물리적으로 정직한 결말)
- **현상 토글** — 광자 궤적 발사 (Space), 아인슈타인 링 (E), 스파게티화 (T), 상대론적 제트 (J), 중력렌즈 돋보기 (G), 광도 곡선 (V), EHT 관측사진 비교 (4) — 켤 때마다 설명 카드 표시
- **이론 배경 패널** — 상황에 맞는 지배 방정식 카드 (X, 고급 난이도(C)에서 자동 표시)
- **MR 버전** — 한 손으로 잡아 옮기고 두 손으로 크기를 조절하는 방 크기 블랙홀. 손 레이 버튼
  메뉴에 가이드 투어·탄생·원반 색상·스핀·관측사진·난이도가 올라가 있습니다. **일부러 옮기지
  않은 것들**: 낙하 체험(머리는 가만있는데 시야만 움직이는 전형적인 멀미 유발, 게다가 패스스루에선
  진짜 바닥이 그대로 있음), 병합(방을 별밭으로 바꿔 MR 전시가 도중에 VR이 됨), 질량 순환(지평선이
  관람객을 삼킬 때까지 커지는데 블랙홀은 팔 하나 거리), 아인슈타인 링·렌즈 돋보기(둘 다 블랙홀
  *뒤*의 밝은 광원이 필요한데 패스스루의 배경은 관람객의 거실), 광도곡선·수식 패널(데스크톱 밀도의
  잔선 그래픽은 MR 글자 크기에서 읽히지 않음). 가이드 투어는 아인슈타인 링 단계를 아예 건너뛰고
  (없는 것을 20초 동안 설명하느니), 하단 번호도 이 씬에 실제로 있는 단계 수로 다시 셉니다.

| 분류 | 키 |
|---|---|
| 체험 | **F1** 가이드 투어(N/B) · **F2** 탄생 · **F3** 낙하 · **F4** 병합 · **F9** 우리은하 전시로 · **Esc** 건너뛰기/중단 |
| 블랙홀 | **1** 원반 색상 · **2** 질량 · **3** 스핀 · **4** 관측사진 비교 |
| 현상 | **Space** 광자 · **E** 아인슈타인 링(A/D) · **T** 스파게티화 · **J** 제트 · **G** 렌즈 · **V** 광도곡선 |
| 시스템 | 우클릭 회전 · 휠/W/S 줌 · **R** 리셋 · **L** 라벨 · **I** 정보 · **X** 수식 · **U** 몰입 · **M** 소리 · **K** 언어 · **P** 성능 · **F10** 처음으로 · **F12** 스냅샷 · **H** 도움말 · **C** 난이도 |

## 2 · 우리은하 (`MilkyWayShowcase` / `MilkyWayMR`)

하이브리드 은하: **레이마치 볼륨 모델**(막대·밀도파 나선팔·먼지 소광·HII 영역·따뜻한 벌지)에
먼지가 실제로 감쇠시키는 **~48만 개 베이크드 점별**을 겹칩니다. 나레이션 체험 9종:

- **F1 줌 여행** — 태양계에서 은하 전체까지, "우리는 여기" 링과 함께
- **F2 밤하늘** — 밤 언덕에서 이륙해, 밤하늘의 은하수 띠가 원반을 안에서 옆으로 본 모습임을 확인
- **F3 안드로메다 조우** — 2025년 결과(충돌 확률 약 50%의 동전 던지기 — 옛 "확정"이 아님)로 서술.
  M31 곁에서 우리은하를 바라보는 시점, 조석 꼬리, 밀코메다, 그리고 시간 되감기
- **F4 은하 투어** — 7정거장 해부학 수업 (벌지와 막대 · 밀도파 나선팔 · 먼지 레인 · 별 탄생 지대 · 태양의 자리 · 헤일로와 암흑물질)
- **F5 우주 줌아웃** — 국부은하군 → 우주 거대구조 (필라멘트를 따라 5만 2천 개 임포스터 은하)
- **F6 태양계 투어** · **F7 회전 곡선 실험실** (암흑물질의 증거, 인터랙티브) · **F8 은하 동물원** (허블 분류의 볼륨 표본들)
- **F9 궁수자리 A\* 크로스오버** — S별 무리를 지나 은하핵으로 다이빙, 블랙홀 전시로 착지
- **MR 버전** — 지름 ~1.1m 미니어처 은하를 잡고 돌리고 양손으로 크기 조절. 나선면이 보이도록
  관람자 쪽으로 기울임, 부위 이름표, 금색 태양 링, 카메라 대신 하이라이트 링이 가리키는 가이드 투어.
  메뉴: 은하 투어 · 이름표 · 자전 · 원위치(처음 자리와 크기로 복귀) · 처음으로. 손으로 잡고 있는
  동안에는 은은한 자전이 멈춥니다

## 3 · 태양계 (`SolarSystemShowcase` / `SolarSystemMR`)

**실측 텍스처 맵**(행성·달·토성 고리 스트립)과 실제 자전축 기울기·역행 자전, 행성색 혜성꼬리
궤도선, 보정된 시간을 갖춘 정밀 오러리: 자전과 대기 흐름은 정직한 공용 시계(실제 1시간 ≈ 1.5초),
궤도는 가독성 시계(케플러 비율 유지)로 돕니다.

- **행성 클릭**으로 줌인; **F1 행성 투어** — NASA 팩트 스트립이 붙은 9정거장 나레이션
- **F2 진짜 크기** — "보기 좋은 지도"의 고백: 궤도는 AU 비례로, 천체는 실제 비율로 —
  태양계가 사실은 거의 완벽하게 텅 빈 공간임이 드러납니다
- **대기 역학** — 목성의 줄무늬 시어와 대적점 소용돌이(사진 맵 위 유계 2위상 플로우 맵), 금성 초회전, 얼음행성 바람, 지구 구름 표류 — 전부 실제 풍속을 전시 시계로 환산
- **MR 버전** — 가슴 높이에 뜬 방 크기 오러리(해왕성 궤도 ≈ 1.2m). 이 전시의 핵심 동작은
  **행성 탭**입니다: 조준해 트리거를 당기면 오러리가 페이드 아웃되고 그 행성 하나가 눈앞
  읽기 거리에서 지름 25cm로 떠올라 자전하며, 데스크톱 투어와 같은 NASA 팩트 스트립을 곁에
  붙입니다(**돌아가기**로 복귀). 메뉴: 행성 투어 · 시간 배속 · 이름표 · 처음으로. 리그를
  축소시키던 진짜 크기 시퀀스는 삭제됐습니다 — 포커스 카드와 리그 스케일을 두고 싸웠고,
  이제 이 전시가 딛고 선 동작은 탭입니다

## 4 · 성운과 성단 (`NebulaShowcase` / `NebulaMR`)

심우주 대표 천체 6종의 갤러리 — 오리온 대성운·말머리·플레이아데스·고리 성운·게 성운·오메가
센타우리. 별의 생애 단계마다 하나씩, 각 천체의 **실제 하늘 영역 DSS2 서베이 사진**을 배경으로
한 번에 하나씩 전시됩니다. 표본 전환은 페이드 아웃/인으로 진행되고(블랙아웃 뒤에서 교체가
끝나므로 끊김이 없습니다), 정지 뷰에서도 카메라가 느리게 2축 드리프트하며 볼륨과 사진 배경
사이에 시차를 만듭니다.

- **형태 맞춤 볼류메트릭** — 성운 유형마다 전용 레이마치 모델: 난류 Hα/OIII 발광(오리온),
  가운데가 진짜로 빈 카메라 지향 토러스(고리), 싱크로트론 안개 위 성긴 필라멘트 레이스(게),
  줄무늬 반사 안개(플레이아데스), 베이크드 점구름 구상성단(ω Cen)
- **말머리는 하이브리드 디오라마** — 기둥 실루엣을 **실제 관측 사진에서 추출**(마스크 텍스처로
  베이크)해 침식된 먼지 볼륨으로 압출하고, 말을 지운 실사 IC 434 커튼 앞에 세웠습니다.
  카메라 드리프트가 둘 사이 시차를 만듭니다
- **"별의 일생"** — 6표본을 하나의 이야기로 엮는 나레이션 투어: 구름 → 차가운 먼지 → 성단 →
  행성상성운 → 초신성 → 살아남은 자들, 그리고 순환
- **MR 버전** — 도구가 아니라 **진열장**입니다. 6표본이 한 뿌리 아래(~0.8m)에서 한 번에 하나씩
  전시되고, 박물관 라벨이 따라다니며, 말머리는 방에 떠 있는 섀도박스입니다. 관람객은 손으로
  표본을 넘기거나(◀ 이전 천체 / 다음 천체 ▶) "별의 일생" 투어에 방을 맡기면 되고, 체류 타이머는
  그 사이 빈틈만 채워서 아무도 조작하지 않아도 진열장이 계속 순환합니다. 집어 들 수는 없습니다 —
  볼류메트릭 표본 6개를 들고 다닐 이유가 없고, 원위치 버튼 없는 잡기는 진열장을 아무 데나
  놓아두게 만듭니다

## 헤드셋 조작

MR에는 키보드가 없으므로 모든 전시가 같은 세 가지를 갖습니다: 버튼과 탭 대상을 겨누는 **손 레이**,
전시물을 드는 **잡기**, 그리고 월드 프레임 아래쪽의 **버튼 메뉴**. 메뉴는 곧장 `DesktopControls`를
호출합니다 — 순환·토스트·4개 언어가 전부 거기 있으니 두 버전이 갈라질 수 없습니다.

| 동작 | 하는 일 |
|---|---|
| 조준 + 트리거 | 메뉴 버튼 누르기, 태양계 오러리에서 행성 탭, 투어 카드 조작 |
| 한 손 잡기 | 블랙홀·은하 미니어처·포커스된 행성 옮기기 |
| 두 손 잡기 | 크기 조절 (양손 스케일링 허용) |
| 도슨트 오브 찌르기 | 지금 말하는 문장 일시정지 / 재개 |

프레임은 씬 원점이 아니라 **씬에 들어온 순간의 머리 자세 기준으로** 배치됩니다. Quest의 월드
원점은 방을 설정한 자리이므로, 고정 앵커를 쓰면 정확히 그 자리에서 시작하지 않은 사람 뒤에 현관문이
걸립니다. 한 번 놓인 뒤에는 월드 고정 — 머리를 쫓아다니는 메뉴는 헬멧 HUD처럼 느껴집니다 — 이지만,
손이 닿는 범위를 벗어나면(3.2m 초과, 0.9m 미만, 시선에서 75° 이상) 1.5초 뒤 앞으로 미끄러져
돌아옵니다.

MR의 읽기 텍스트는 데스크톱의 **1.4배**입니다. 1920px 프레임을 1.6m 거리에 2.6m 폭으로 걸면 20px
한 줄이 약 1°인데, 라틴 문자에는 충분해도 한글에는 부족합니다 — 라틴 한 글자 자리에 획 두세 개가
들어가는 음절 블록이 뭉개져 회색 질감이 됩니다. 늘어나는 건 세로뿐입니다: x는 캔버스 실린더 위의
각도가 되고, 가장 넓은 버튼 줄은 이미 70° 편의 예산을 다 씁니다.

| 씬 | 메뉴 |
|---|---|
| `MRTitle` | 전시 카드 4장 + 언어 줄. 도슨트 오브가 맞이하고, 45초간 고르지 않으면 첫 카드를 가리킵니다 |
| `BlackHoleMR` | 가이드 투어 · 블랙홀 탄생 · 원반 색상 · 스핀 · 관측사진 · 설명 난이도 ⁄ 스파게티화 · 제트 ⁄ 처음으로 |
| `MilkyWayMR` | 은하 투어 · 이름표 · 자전 · 원위치 ⁄ 처음으로 |
| `SolarSystemMR` | 행성 투어 · 시간 배속 · 이름표 ⁄ 처음으로 — 여기에 행성 탭 후 **돌아가기** |
| `NebulaMR` | 별의 일생 투어 · ◀ 이전 천체 · 다음 천체 ▶ ⁄ 처음으로 |

1.6m 거리에서 편의 예산 안에 들어오는 최대 줄 길이가 버튼 6개입니다. 줄이 짧은 이유, 그리고 모든
전시의 유일한 출구가 타이틀인 이유가 이것입니다 — 전시끼리 바로 건너뛰게 했더니 메뉴마다 목적지가
셋씩 붙고 집으로 가는 길이 네 번째로 찾아야 하는 것이 됐습니다.

## 실제로 반영된 물리 (블랙홀)

화면의 기하는 실제 방정식의 수치해입니다 — 렌즈 효과를 "그려 넣은" 것이 아닙니다:

| 항목 | 수식 | 비고 |
|---|---|---|
| 빛의 휘어짐 | 널 측지선 ODE d²**x**/dλ² = −(3/2)h²**x**/r⁵ (GM=c=1) | 픽셀마다 leapfrog 적분. 그림자(b_crit = 3√3 GM/c² ≈ 2.6 Rs)·광자 고리·아인슈타인 링·원반 위아래 아치는 전부 이 적분에서 **저절로 나타나는** 결과 |
| 커 시공간 | 커–실트 해밀토니안 Φ = H(1+l·q)² | 지평선 r₊ = M+√(M²−a²), 순행 ISCO는 Bardeen–Press–Teukolsky 공식 |
| 비밍·적색편이 | δ = 1/(1−β·cosθ), g = √(1−Rs/r), I ∝ (δg)³, T_obs = T·δg | 원반 좌우 밝기 차는 계산 결과이지 텍스처가 아님 |
| 원반 온도 | Shakura–Sunyaev T ∝ r^(−3/4), 플랑크 궤적 흑체색 | 10 M☉ 기준 ~1200만 K, 질량 프리셋 간 T ∝ M^(−1/4) |
| 시간 지연 | 두 시계 모두 √(1−Rs/r) | 관찰자 시계는 카메라 실거리 사용, "먼 우주 1시간 = X분"은 정적 관찰자 기준 정확한 값 |
| 실제 스케일 | Rs = 2.953 km × M/M☉, 그림자 지름 = 5.2 Rs | 패널의 10 M☉/궁수자리 A*/M87* 수치는 실제 값 |
| 쌍성 나선 강하 | Peters 감쇠 a(t) = a_f+(a₀−a_f)(1−t/T)^¼, ω² = M/a³, f_GW = 2f_궤도 | 잔해 질량 95%·스핀 0.69는 GW150914 측정값 |
| 광자 발사기 | 동일한 측지선 ODE를 CPU에서 적분 | 임계거리 안쪽 포획은 연출이 아닌 계산 결과 |

다른 전시의 수치도 정직합니다: 은하의 비례(원반 반지름 ~16 kpc, 태양 8.2 kpc, 막대 ~27°),
회전 곡선 실험실의 평탄한 곡선 vs 케플러 예측, 태양계 팩트 스트립·자전축·역행 자전,
2025년 안드로메다 확률 — 전부 실제 값입니다.

## 간소화·연출된 것들

엄밀하지 **않은** 부분을 정직하게 밝힙니다:

- **시간·공간은 어디서나 압축.** 병합은 수개월을 ~40초로(케플러 비율 유지), 원반·행성 궤도는 가독성 시계로 과속, 안드로메다 조우는 ~100억 년을 압축. 질량 프리셋의 수치는 정확하지만 화면상 크기 비율은 연출.
- **쌍성 렌징은 두 슈바르츠실트 굴절의 중첩.** 두 블랙홀의 해석적 계량은 존재하지 않고 마지막 궤도들은 수치상대론의 영역. 링다운 오디오는 감쇠 사인파(준정규 모드 스펙트럼 아님). 중력파 "고리"는 보이지 않는 변형률의 시각화.
- **복사 전달 없음.** 원반 밝기, 은하의 방출/소광 모델, 난류 노이즈와 밝은 매듭은 물리가 빚은 프로시저럴 아트이지 MHD/RT 시뮬레이션 출력이 아님. 블룸·노출은 가독성 위주 튜닝.
- **낙하 등 시네마틱은 연출**이며 고유시간 적분이 아님 (자막의 *서술*은 올바른 물리).
- **스파게티화**는 가독성용 캡 스트레치 (실제 조석 기울기는 Δa ∝ 1/r³); 초신성·제트·인트로는 물리적 동기가 있는 VFX.
- **은하 조우는 안무된 모프**이지 N체 시뮬레이션이 아님; 조석 꼬리·위상 혼합은 실제 타임라인을 따르는 셰이더 변형.
- **행성 대기 움직임**은 실제 풍속으로 사진을 흘리는 플로우 맵 — 패턴 속도는 실제, 유체역학은 시뮬레이션 아님.
- 커 모드는 순행 적도 박원반만 표시; 제트는 장식 (Blandford–Znajek 없음).
- **MR 태양계 포커스 카드는 모든 천체를 똑같은 25cm로 보여줍니다.** "하나의 세계가 어떻게
  생겼는가"를 다루는 카드이고, 실제 상대 크기는 별개의 수업입니다 — 섞으면 둘 다 안 남습니다.

앱 내 이론 카드(X)마다 해당 주제가 계산인지 연출인지 명시되어 있습니다.

## 수업 활용 시 참고

- **스톱워치 말고 숫자를 믿으세요.** 패널 값(Rs·그림자 크기·온도·지연 배율·행성 데이터)은 정확하고, 화면상 시간·각크기는 압축입니다.
- **시간 지연 시계는 *정지(호버링)* 관찰자 기준.** 궤도·낙하 관찰자는 속도 항이 추가로 필요합니다 — 탐사선이 "블랙홀 곁에 떠 있다"고 서술되는 이유.
- **색은 물리적 색이지만 실제 관측 이미지와 다릅니다:** EHT 사진은 전파 간섭계의 false color이고, 광학으로 보면 눈이 멀 만큼 밝습니다. 비교 모드(4)로 직접 토론해 보세요.
- **지평선 안쪽은 근거 있는 삽화.** 안에서 밖으로는 아무것도 보고할 수 없고, 자막도 그렇게 말합니다 — 그 주장 자체가 물리입니다.
- **안드로메다 이야기는 불확실성 교육에 좋습니다**: 2025년 재분석이 "확정 충돌"을 동전 던지기로 바꿨습니다 — 과학이 스스로를 갱신하는 좋은 예.
- 나레이션 대본 = 화면 자막(4개 언어 모두) — 인용해도 안전하며, 수정 시 edge-tts로 오디오를 재생성하세요.

## 빌드 방법

모든 씬은 **메뉴로 생성되는 빌드 산출물**(`Tools/…/Create … Scene`)이고 *Build Settings*에 이미
등록되어 있습니다 — `TitleScreen`(인덱스 0)이 데스크톱·웹의 부팅 씬입니다. Android와 Windows는 씬
목록 전체를 담습니다: MR 씬은 헤드셋 밖에서는 비활성이고, HMD가 실행 중이면 `TitleScreen`이
`MRTitle`로 전환됩니다. Quest APK는 그 전환에 의존하지 않습니다 — `BuildAndroid`가 `MRTitle`을
인덱스 0으로 올려서 헤드셋 빌드에는 MR 현관문만 존재합니다. WebGL 사이트 빌드만 예외로 데스크톱 5씬만 담습니다 — MR 씬을 넣으면
XR 샘플 에셋(핸드 레코딩, 데모 텍스처, 약 14MB)이 데이터 파일로 끌려들어옵니다.

*Build Profiles*보다 `Tools/Cosmos/` 메뉴를 쓰는 편이 낫습니다. 플랫폼별로 씬 목록과 출력 경로가
고정되어 있습니다.

| 메뉴 항목 | 메서드 | 출력 |
|---|---|---|
| Build WebGL (Site, desktop scenes) | `MilkyWay.WebGLSiteBuild.Build` | `Builds/WebGL/` |
| Build Android (Quest APK) | `MilkyWay.WebGLSiteBuild.BuildAndroid` | `Builds/Android/CosmosEdu.apk` |
| Build Windows (full exhibit) | `MilkyWay.WebGLSiteBuild.BuildWindows` | `Builds/Windows/CosmosEdu.exe` |

씬 자체도 같은 방식으로 재생성합니다. `Tools/Cosmos/Rebuild All MR Scenes`가 MR 빌더 다섯 개를
순서대로 실행합니다(전시 4종 + `MRTitle`) — 씬은 코드이므로 빌더를 고쳐도 재생성 전에는 반영된 게
아니고, 메뉴를 하나씩 누르는 방식은 꼭 하나를 빠뜨립니다.

세 항목 모두 **활성 타깃이 아닌 플랫폼은 빌드를 거부**하고, 타깃만 전환한 뒤 다시 실행하라고
안내합니다. 플레이어 스크립트는 그 시점의 활성 타깃 디파인으로 컴파일되므로, Web 타깃에서 곧바로
Android를 빌드하면 `UNITY_WEBGL` 분기가 APK에 박히고, 전환 자체가 도메인 리로드를 예약해 호출
도중에 빌드가 끊깁니다.

### PC (Windows)

1. `File → Build Profiles` → 플랫폼 **Windows**.
2. 스크립팅 백엔드: **Mono**는 그대로 동작; IL2CPP 모듈이 설치돼 있으면 전환 가능
   (`Project Settings → Player → Configuration`).
3. `Tools/Cosmos/Build Windows (full exhibit)` 실행 후 `Builds/Windows/CosmosEdu.exe` 실행.

### WebGL

1. `File → Build Profiles` → 플랫폼을 **WebGL**로 전환.
2. 유지해야 하는 플레이어 설정(리포에 이미 설정됨):
   - **WebGL Template: `PROJECT:CosmosEdu`** — 번들 템플릿이 브라우저의 캔버스 포커스(키 입력)와
     우클릭 드래그 궤도를 고칩니다. 기본 템플릿은 둘 다 깨집니다.
   - 압축 **gzip** — 호스팅 서버가 `Content-Encoding: gzip`을 보내야 합니다.
   - 모든 셰이더는 `#pragma target 3.5` 유지 (SM 4.5 기능은 WebGL 빌드를 조용히 망가뜨림).
3. `Tools/Cosmos/Build WebGL (Site, desktop scenes)` 실행 후 로컬 서빙:
   ```
   python Builds/serve_webgl.py    # http://localhost:8123 (Content-Encoding 처리)
   ```
   단순 `python -m http.server`는 gzip 빌드에서 동작하지 않습니다.
4. WebGL 알려진 제한: 포스트프로세싱 꺼짐(URP FSR 셰이더 비호환 — PC는 무관), 오디오 스트리밍
   비활성(클립은 로드 시 압축 해제).

### MR (Meta Quest, 패스스루)

1. `File → Build Profiles` → 플랫폼 **Android** (Android 모듈 + OpenXR 지원 설치).
2. 스크립팅 백엔드 **IL2CPP** + 아키텍처 **ARM64** (Quest 필수 조합).
3. `Project Settings → XR Plug-in Management → Android`: **OpenXR** + Meta Quest 기능 그룹 활성화
   (패스스루는 Meta OpenXR 기능 필요; 각 MR 씬의 AR 카메라가 AR Foundation으로 구동).
4. `Tools/Cosmos/Build Android (Quest APK)` 실행 후 설치: `adb install -r Builds/Android/CosmosEdu.apk`.
5. 기기에서는 `MRTitle`(패스스루 선택 화면, MR 전시 4종)로 바로 부팅하며, 프레임은 관람객이 서 있는
   자리 정면에 걸립니다. 에디터에서는 MR 씬에서 Play만 누르면 **XR Device Simulator**가 떠서
   키보드/마우스로 손 레이를 테스트할 수 있습니다.
6. Quest Link 초기 셋업처럼 "지금 헤드셋이 씬을 돌리는 건지 시뮬레이터인지" 판단이 어려울 때는
   `MRDiagnostics`가 디스플레이 서브시스템·등록된 입력 장치·카메라를 무엇이 움직이는지·실제로
   움직이긴 하는지를 덤프합니다. 에디터 로그에서 `[MRDIAG]`를 찾으세요. 기능이 아니라 임시
   발판이므로, 셋업이 안정되면 지우면 됩니다.

### 헤드리스 빌드, 그리고 열려 있는 에디터로 빌드하기

같은 세 메서드를 커맨드라인에서 한 번에 한 타깃씩 실행할 수 있습니다:

```
Unity.exe -batchmode -quit -projectPath <repo> -buildTarget Android \
          -executeMethod MilkyWay.WebGLSiteBuild.BuildAndroid -logFile android.log
```

`-buildTarget`이 `-executeMethod` 실행 전에 타깃을 활성화하므로 위의 거부 조건을 통과합니다.
**에디터를 먼저 닫아야 합니다** — 한 프로젝트를 두 Unity 인스턴스가 열 수 없어서, 락
(`Temp/UnityLockfile`)이 잡혀 있으면 배치모드가 즉시 중단됩니다. 스크립트로 돌릴 때 함정 두 가지:

- `Unity.exe`는 GUI 서브시스템 바이너리라서, 셸에서 `&`나 `start`로 띄우면 빌드 종료가 아니라 프로세스
  생성 시점에 곧바로 반환됩니다(PowerShell은 `Start-Process -Wait`). 그대로 세 개를 띄우면 순서대로
  대기하지 않고 프로젝트 락에서 서로 충돌합니다.
- 성공 판정은 산출물 타임스탬프가 아니라 로그의 `[…Build] Succeeded` 줄로 하세요. Windows 플레이어의
  `CosmosEdu.exe`와 `UnityPlayer.dll`은 에디터 설치 폴더에서 원본 mtime째로 복사되고, 증분 WebGL
  빌드는 IL2CPP 출력이 같으면 `WebGL.wasm.gz`를 손대지 않습니다 — 둘 다 최신인데 낡아 보입니다.

에디터를 닫지 않고 빌드하려면 `Temp/cosmos-autobuild.txt`에 타깃 이름(`webgl`, `android`,
`windows`)을 써 넣으면 됩니다. `AutoBuildTrigger`가 다음 도메인 리로드에서 이를 읽어 필요하면 타깃을
전환하고, 그 뒤 이어지는 리로드에서 빌드합니다 — 요청 파일은 1차 패스에서는 남고 `BuildPlayer`
