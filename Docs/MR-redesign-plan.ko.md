# 우주 전시관 MR 전면 리디자인 기획서

*2026-07-27 · CosmosEdu (구 BlackHoleEdu) · 대상: Quest 3 주력, Quest 2 호환*

---

## 0. 전제

| 항목 | 가정 |
|---|---|
| 주력 기기 | Meta Quest 3 (Adreno 740, 컬러 패스스루) — Quest 2는 축소 모드 |
| 사용 맥락 | ① 전시장 워크업 관람 (첫 착용자 포함) ② 교실 수업 보조 |
| 세션 길이 | 전시당 6–10분, 전체 25–35분. 워크업 관람객은 8분 안에 "와" 순간 3번 |
| 이동 범위 | 2m×2m 스탠딩 기본, 착석 모드 필수 지원 (교실은 대부분 착석) |
| 유지 자산 | 물리 정직성(이 프로젝트의 차별점), 4개국어 나레이션 파이프라인, 프로시저럴 생성 |

이 문서는 "PC 콘텐츠를 어떻게 MR에 넣을까"가 아니라 **"이 교육 목표를 MR 매체가 어떻게 가장 잘 달성하는가"** 에서 출발합니다. 답이 데스크톱 버전과 같은 형태일 이유가 없습니다.

## 1. 현재 상태 진단 — 왜 "이식 수준"인가

### 1.1 구조적 증거

MR 전용 코드는 총 **~1,100줄**입니다 (MRControls 177 + 은하/태양계/성운 컨트롤 ~400 + MRWorldCanvas 168 + MRSpaceWindow 169). 데스크톱 시뮬레이션·투어·UI 수만 줄 위에 얹힌 어댑터 계층이고, 패턴이 전부 동일합니다:

```
데스크톱 씬 → 미니어처로 축소 → 방 가운데 배치 → 1920×1080 UI 프레임을
실린더에 걸기 → 투어의 카메라 이동을 하이라이트 링으로 치환
```

이것은 **"3D 모델 뷰어"** 이지 MR 경험이 아닙니다. 관람객이 하는 일: 서서, 미니어처를 보고, 패널의 글을 읽고, 버튼을 누른다 — 전부 모니터 앞에서 하던 일입니다.

### 1.2 UX 문제 (구체적)

- **UI가 곧 콘텐츠 구조**: 1920×1080 데스크톱 프레임(`MRWorldCanvas`)이 관람객을 둘러싸는 실린더로 존재. HMD에서 장문 텍스트 패널은 읽기 부담이 크고, 시선이 전시물과 패널 사이를 왕복. 이론 패널의 잔글씨 33 arcmin은 "읽을 수 있다"이지 "읽고 싶다"가 아님
- **수동적 관람**: 투어가 "링이 가리키는 곳을 보라"는 지시. 손이 있는 매체에서 손이 할 일이 거의 없음 (은하 잡고 돌리기·별공 던지기가 전부)
- **공간 미사용**: 콘텐츠가 방 가운데 1점에 존재. 관람객의 방 — 벽·바닥·책상·걸어 다닐 수 있음 — 이 아무 역할이 없음. 패스스루가 "배경"일 뿐 "무대"가 아님
- **스케일이 언어로만 존재**: "은하는 10만 광년"이라고 *말하지만*, MR의 최강 무기인 **몸으로 느끼는 스케일 대비**를 안 씀

### 1.3 그래픽/성능 문제

- **데스크톱 셰이더 그대로**: 지오데식 레이마칭(픽셀당 ODE 적분), 은하/성운 볼류메트릭 레이마치가 풀 해상도 알파 블렌딩으로 돎. 모바일 타일 GPU에서 볼류메트릭 오버드로우는 최악의 부하 패턴
- **하프해상도 볼륨 버퍼 없음**: 볼륨을 저해상 오프스크린에 그리고 업샘플하는, 모바일 VR 볼류메트릭의 표준 기법이 미적용
- **FFR(고정 포비티드 렌더링) 상태 미확인**: OpenXR 기능 목록에는 있으나 실제 활성·레벨 미검증. 프래그먼트 바운드 씬에서 10–25% 공짜 절감을 안 쓰고 있을 가능성
- **프레임레이트 정책 부재**: 72Hz 고정 요청(`SetDisplayRefreshRate`), Dynamic Resolution, SpaceWarp 폴백 등 어떤 정책도 코드에 없음. `AdaptiveResolution`은 모바일 전반용이지 VR 프레임 페이싱과 무관
- **측정 데이터 제로**: 어떤 씬이 몇 ms인지 아무도 모름. 최적화 이전에 프로파일링부터

### 1.4 콘텐츠 구성 문제

- 4개 전시가 **서로 무관한 방**: 씬 전환으로만 연결, 내러티브 없음
- 나레이션이 **화면 자막 + 보이스오버**: 공간 매체에서 목소리의 주인이 없음
- 교육 레이어(퀴즈 등)가 데스크톱 폼 그대로

## 2. 콘셉트 — "당신의 방이 우주가 된다"

### 2.1 단일 내러티브: 스케일의 여행

4개 전시를 하나의 이야기로 묶습니다. **관람객의 방(10⁰ m)에서 출발해, 한 전시가 끝날 때마다 우주가 한 단계 커진다**:

```
방 (10⁰) → 태양계 (10¹³) → 은하 (10²¹) → 극한: 블랙홀 · 성운 (별의 삶과 죽음)
```

전시 사이의 "이동"이 곧 교육 콘텐츠입니다: 태양계가 모래알로 줄어들며 은하가 되고, 은하의 한 점을 확대하면 성운이 되는 **연속 줌**이 전시 전환을 대체합니다. (기존 `CosmicZoomOut`·`SgrACrossover` 로직 재활용 — 데스크톱엔 이미 이 연결이 있는데 MR에서 버려짐)

### 2.2 도슨트 오브 — 나레이션의 공간화

주먹 크기의 발광 구체("별이"라 하자)가 모든 전시를 관통하는 안내자:

- 나레이션 음성이 **오브 위치에서 공간 음향**으로 남 (지금: 머리에 붙은 무지향 소리)
- 설명 대상 옆으로 **날아가서 가리킴** — 하이라이트 링의 상위 호환. "저길 봐"가 아니라 시선 유도가 자연스럽게 됨
- 자막은 오브 옆 **1–2줄 칩**으로만. 장문은 전부 음성으로
- 관람객이 오브를 **손가락으로 톡 치면** 일시정지/재개, 잡고 있으면 "다시 말해줘"
- 구현: 위치+빌보드 칩+간단한 스프링 이동. 기존 `NarrationLines` 파이프라인 그대로 사용. 첫 페이즈에 만들어 전 전시에 공용

### 2.3 허브 재설계 — 메뉴가 아니라 로비

현재 MRTitle: 공중에 뜬 카드 4장 = 포스터. 재설계: **네 전시의 "표본"이 관람객 주위 바닥·공중에 실물 크기 미니어처로 배치**:

- 무릎 높이에 도는 태양계 오러리, 어깨 높이의 은하 원반, 손바닥만 한 블랙홀(주변 별빛이 휘는), 발치의 성운 안개
- **표본에 손을 뻗어 잡으면 그 전시가 시작** — "카드를 골라 클릭"이 아니라 "우주를 집어 든다"
- 언어 선택은 도슨트 오브가 첫 만남에서 처리 ("한국어로 할까요?" 4개국어 순환 + 손 포크)
- 기존 자산으로 조립 가능: 은하 미니어처·별공·오러리 프리팹이 전부 있음

## 3. 전시별 재기획

각 전시: **핵심 경험 하나**(그 매체에서만 가능한 것)에 집중하고, 데스크톱의 기능 나열(토글 11개…)은 버립니다.

### 3.1 태양계 — "방을 가로지르는 빛"

**핵심 경험: 스케일의 고백을 몸으로.** 데스크톱 F2("진짜 크기")가 이 프로젝트 최고의 교육 콘텐츠인데 MR에서 죽어 있음. MR 네이티브로 다시:

1. 친근한 오러리(현행)가 방 가운데. 행성을 **집어서 귀에 대면** 그 행성의 소리(대기 데이터 기반), 놓으면 궤도로 복귀
2. "진짜 크기" 발동: **방의 가장 긴 벽면 스팬이 1 AU가 되도록 축척을 잡고**(4 m 방이면 태양 = 골프공 ∅3.7 cm) 태양이 벽에 붙는다. 도슨트가 "지구를 찾아보세요" — 지구는 **방 반대편의 ∅0.3 mm 소금 알갱이**. 관람객이 실제로 걸어가서 찾는다 (착석 모드: 손 레이로 스캔)
3. 피날레 "빛의 속도": 태양에서 광자 하나가 출발해 **방을 실속도 비율로 횡단** — 자몽-태양 스케일에서 광속은 초속 수 cm. 지구까지 8분 19초 걸리는 것을 30초 압축으로 보여주고, "해왕성까지는 4시간"에서 끝. 빛이 느린 게 아니라 우주가 큰 것
- 컷: 데스크톱 투어 9정거장 → 3막 구조로 압축. NASA 팩트 스트립 패널 → 도슨트 대사로

### 3.2 우리은하 — "은하 안에 서다"

**핵심 경험: 내부 시점.** 미니어처를 *보는* 건 데스크톱도 함. MR만 할 수 있는 것은 **은하가 방 크기가 되어 관람객이 그 안에 서는 것**:

1. 어깨 높이 미니어처(현행)로 시작 — 잡고 돌리는 촉각적 만남 유지
2. 도슨트: "우리가 어디 있는지 보여드릴게요" → 은하가 **방을 삼킬 때까지 확대** (`MRSpaceWindow` 룸스왑 재활용). 관람객 가슴 높이에 태양 링, 발밑과 머리 위로 원반의 별들, 8.2 kpc 저쪽에 은하핵이 빛남
3. **걸으면 파랄락스**: 두 걸음 옆으로 → 근거리 별들이 크게 흐르고 핵은 거의 안 움직임 — "별까지의 거리"를 다리로 이해
4. 밤하늘 연결(기존 `NightSkyConnection`): 원반 안에서 위를 보면 **은하수 띠가 왜 띠인지**가 그냥 보임. 이게 이 전시의 "아하"
5. 피날레: 핵으로 빨려들며 블랙홀 전시로 (기존 `SgrACrossover`)
- 성능: 내부 시점은 볼륨 레이마치 최대 부하 → §5의 하프해상도 버퍼가 전제조건

### 3.3 블랙홀 — "손바닥 위의 심연"

**핵심 경험: 위험한 물건을 손에 들다.** 실물 블랙홀의 공포와 매혹은 근접성에서 옴:

1. 도슨트가 **관람객 손바닥에 구슬 크기 블랙홀**을 놓아줌 (기존 팜 소환 확장). 주변 별빛(가상 배경)이 구슬 주위로 휘는 것이 첫 인사 — 렌징을 "설명"이 아니라 "목격"
2. **별공 급식**(기존 확장): 별공을 던지면 조석 파괴 — 스파게티화 스트림이 강착원반으로 감기며 원반이 실제로 밝아지고 뜨거워짐(질량 카운터 증가). 물리 정직성 유지: 포획 단면은 실제 지오데식
3. **질량 다이얼**: 두 손으로 벌리면 태양질량 10 → Sgr A*. 방이 좁아 보이기 시작할 때 도슨트: "실제 Sgr A*의 그림자는 수성 궤도만 합니다"
4. 병합 시퀀스(기존 GW150914)는 **룸스왑 후 실공간 스케일**로 유지 — 이미 올바른 MR 설계. 햅틱 처프 유지
5. 낙하 체험은 **컴포트 게이트** 뒤로 (착석+숙련자 선택). 벡션 최강 콘텐츠를 기본 동선에서 제외
- 기술 제약 명시: **Quest 패스스루는 셰이더에서 샘플 불가**(프라이버시 정책) → "방이 휘는" 연출은 불가능. 룸스왑(`MRSpaceWindow`)이 유일한 정답이며 이미 구현됨. 이 자산을 중심에 둘 것

### 3.4 성운 — "방을 채우는 별의 요람"

**핵심 경험: 안개 속에 들어가기.** 성운은 "보는 대상"이 아니라 "들어가는 장소"로:

1. 방에 **오리온 성운의 가스가 스며듦** — 바닥부터 차오르는 저밀도 볼륨 안개(§5의 저해상 버퍼 + 시트 파티클 하이브리드). 손을 **휘저으면 가스가 밀려나고**(간단한 유체 흉내: 손 속도장 → 노이즈 오프셋), 걷어낸 자리에 원시성이 드러남
2. **별의 일생 6표본**(기존)을 방 코너들에 배치 — 요람(오리온)→성단(플레이아데스)→행성상(고리)→초신성 잔해(게)→생존자(오메가센). 관람객이 **방을 돌며** 일생을 순례. 코너 배치는 가디언 경계 기반(§6 MRUK)
3. 말머리 섀도박스(기존)는 유지 — 이미 MR 네이티브 발상
4. 피날레: 게 성운의 중심에서 펄서가 **방 전체를 등대처럼 쓸고**(회전 광선이 실제 벽을 스침 — 패스스루 위 가상 광원 연출), 도슨트: "당신 몸의 철은 이런 폭발에서 왔습니다" → 처음 방으로 줌아웃, 여정 종료

## 4. 인터랙션 문법 (전 전시 공통)

| 거리 | 방식 | 용도 |
|---|---|---|
| 팔 안 | **직접 터치(포크)** | 기본. 행성 집기, 오브 톡, 다이얼 |
| 팔 밖 | 손 레이 + 핀치 | 원거리 선택만. 최소화 |
| 시스템 | **손바닥 펴서 응시** → 팜 메뉴 | 나가기/언어/자막/착석 모드. 유일한 "메뉴" |

- **월드캔버스 실린더 UI는 전시에서 퇴출**. 정보는 ① 도슨트 음성 ② 대상 옆 1–2줄 칩 ③ 팜 메뉴 세 채널로만. (이론 패널 수요는 "더 알아보기" 칩 → 웹 버전 안내로)
- 텍스트 규칙: 칩 최대 2줄×18자, 최소 글자 높이 1.2° (기존 33 arcmin=0.55°의 두 배)
- 컴포트 규칙: 인위적 카메라 이동 금지(룸스왑·줌은 페이드로), 낙하류는 게이트 뒤, 모든 콘텐츠 착석 리치(반경 0.75 m) 안 대체 경로
- 교육 레이어 MR화: 퀴즈 = **물리 조작** (행성을 크기순으로 실제로 놓기, 스펙트럼형 별공을 온도순 걸이에 걸기). 4지선다 패널 금지

## 5. 그래픽 최적화 플랜

### 5.1 프레임 예산 (Quest 3 · 72 Hz)

| 항목 | 예산 |
|---|---|
| GPU 총 | **≤ 11 ms** (13.9 ms − 컴포지터/여유) |
| 볼류메트릭(은하·성운·원반) | ≤ 4.5 ms — 하프해상도 버퍼 전제 |
| 블랙홀 레이마치 | ≤ 3 ms — §5.3 라이트 버전 |
| 불투명 지오메트리+별 파티클 | ≤ 2 ms |
| UI/칩/도슨트 | ≤ 0.5 ms |
| 드로우콜 | ≤ 120 / 트라이앵글 ≤ 1M |
| CPU 메인스레드 | ≤ 9 ms (Update 로직 + 컬링) |

Quest 2 호환 모드: renderScale 0.8, 볼륨 쿼터해상도, 병합 시퀀스 간소화.

### 5.2 즉시 적용 (전 씬 공통, P0)

1. **FFR 활성 확인+설정**: OpenXR Meta 포비이션 레벨 2(정적)부터, 프래그먼트 바운드 확인 후 3. 예상 10–25% 절감
2. **72 Hz 고정** + `OVRManager` 없이 OpenXR `SetDisplayRefreshRate`, 씬 로드 중 90→72 방지
3. **Vulkan + half precision 감사**: 볼륨 셰이더 float→half (색·밀도 누적은 half로 충분, 좌표 계산만 float)
4. **MSAA 정책**: 지오메트리 적은 씬 4x 유지, 볼륨 지배 씬은 2x로 낮추고 절감분을 renderScale에
5. **측정 체계**: OVR Metrics Tool 오버레이 + RenderDoc Meta 포크로 씬별 GPU 타이밍 기록. **모든 최적화는 전후 수치 필수** — 이 문서의 예산표를 CI 문서로 승격

### 5.3 볼류메트릭 — 하프해상도 파이프라인 (P0 최대 과제)

```
[불투명 패스 풀해상도] → [볼륨 전용 오프스크린 ½×½ + 깊이 다운샘플]
→ [블루노이즈 지터 레이마치, 스텝 상한 24] → [깊이 인지 업샘플 합성]
```

- URP Renderer Feature로 구현, 은하 볼륨·성운·강착원반 헤이즈가 공유
- 픽셀 수 ¼ = 볼륨 비용 ~¼. 은하 내부 시점(§3.2)은 이것 없이는 불가
- 엣지 아티팩트는 깊이 인지 업샘플 + 볼륨의 소프트한 특성으로 흡수

### 5.4 블랙홀 레이마치 — MR 라이트 버전

데스크톱 셰이더 포크 금지, `_MRLight` 키워드 분기:

- **편향 LUT**: 슈바르츠실트 광선 굴절각을 충격 매개변수 b의 1D LUT로 사전계산(같은 ODE에서 구움 — 물리 정직성 유지). 픽셀당 적분 → LUT 샘플 1회. 구슬~미니어처 크기(화면 점유 <15%)에서는 시각 차이 없음
- 병합 시퀀스(전천 렌징)만 실적분 유지하되 스텝 ½ + 하프해상도 버퍼
- 원반 온도·빔잉은 이미 해석식 — 그대로

### 5.5 금지 목록

풀스크린 블릿 패스(룸스왑 페이드는 컴포지터 레이어로), GrabPass류, 실시간 그림자, 런타임 텍스처 생성(로딩 시로 이동), 씬당 파티클 시스템 5개 초과.

## 8. 검증 계획

- **성능**: 씬×시점(허브/전시 피크/전환) 매트릭스로 GPU ms 기록, P0 이후 회귀 금지
- **컴포트**: 첫 착용자 3명에게 25분 전체 동선 — 멀미 보고 0건이 목표, 1건이면 해당 콘텐츠 게이트 강화
- **교육 효과**: 관람 전후 3문항 (예: "태양–지구 거리에서 빛은 얼마나 걸리나") — 전시의 존재 이유 측정
- **조작 발견성**: 무설명 첫 착용자가 60초 안에 허브에서 전시 진입 가능한가
